## Open-source approach

When I take an issue, I try to make the maintainer's job easy:

1. Read the repository instructions and existing patterns first.
2. Reproduce or verify the issue before changing code.
3. Keep the diff focused on the requested scope.
4. Add or update tests when behavior changes.
5. Run the relevant lint, test, and build checks.
6. Respond quickly and clearly to review feedback.

I prefer **small, well-tested PRs over broad unrelated refactors**.
